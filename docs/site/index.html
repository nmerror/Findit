FindIt — Campus Lost & Found System

A desktop application for the lost and found office of a campus. Students report what they lost or found, the system matches the two sides, the office verifies the claim and the item goes back to its owner.

Run it in one minute

No database server needed for the demo — the application falls back to an in-memory store with the same data model.

On Linux or macOS

# clone the repository
git clone https://github.com/nmerror/Findit.git
cd Findit

# only if Java is not installed
bash setup-java.sh

# compile and start (demo data)
bash run.sh

On Windows

git clone https://github.com/nmerror/Findit.git
cd Findit

rem only if Java is not installed
setup-java.bat

rem compile and start (demo data)
run.bat

The screens

3. Data management — administrator only: suspend, restore and change the role of an account.
4. Search — one search box over people, items and claims; the other segments join in through the same contract.

What it does

The five modules of the proposal — who owns them and what they do.

ModuleOwnerWhat it does
User login & authenticationSegment 1 Registration and sign-in, PBKDF2 password hashing, sessions with an expiry, role based access control and the audit trail.
Module 1 — item reportingSegment 2 Report a lost or found item with its category, its campus location and a photo; browse and filter the open reports.
Module 2 — matchingSegment 3 Compare the lost and the found reports, score the similarity and propose the pairs that belong together.
Module 3 — claimsSegment 3 & 4 Claim an item, let the office verify the claim with the photo evidence and hand the item back to its owner.
Search & reportSegment 1 One global search over people, items and claims, plus the report of the whole system as a text file or as CSV.

Architecture

Four segments, one code base — nobody has to touch anybody else's code.

Contracts, not imports

Segment 1 declares the interfaces in core/spi. Segments 2, 3 and 4 implement them and register them in the ServiceRegistry at run time. Segment 1 never imports a class of another segment.

One owner per table

Segment 1 writes users and audit_log, Segment 2 writes locations, items and item_images, Segment 3 writes matches and claims, Segment 4 only changes the status of a claim.

A real connection pool

Every query used to open its own TCP connection. Now a pool of eight connections is handed out and returned, and several statements can run in one transaction with a commit or a rollback.

Permission in the service layer

The buttons are not the security. Every service checks the permission of the current user again — the interface only hides what the user may not do.

Database

MySQL 8, eight tables, foreign keys and indexes — created by sql/01_schema.sql.

TablePurposeWritten by
usersThe accounts: name, e-mail, student ID, hashed password, role, statusSegment 1
audit_logEvery action: who, what, when, detailsSegment 1
notificationsThe alerts of the dashboardSegment 1
locationsThe places of the campus where something can be lostSegment 2
itemsThe lost and the found reportsSegment 2
item_imagesThe photo of a reportSegment 2
matchesThe pairs that the matching engine proposesSegment 3
claimsThe claims of the students and their verificationSegment 3 & 4

Every statement is a PreparedStatement with ? placeholders — no string is ever glued into a query. The connection, the pool and the transactions live in db/Database.java and db/ConnectionPool.java.

The Java OOP concepts, where they are

ConceptWhere it is in the code
Classes and objectsUser, Role, Session, OperationResult, DashboardStats — the whole domain model
Encapsulationprivate fields with getters; User.sanitized() never lets the password hash leave the object
InheritanceBaseFrame is the abstract base of every window; LoginFrame, RegisterFrame and MainFrame extend it
Polymorphismevery DAO interface has two implementations — JdbcUserDao for MySQL and InMemoryUserDao for the demo; the application asks for the interface and never for the class
Abstractionthe seven interfaces in core/spi, the abstract BaseFrame, the DAO interfaces in db/dao
Exception handlingtry/catch in the DAOs, DataAccessException and AccessDeniedException, and OperationResult instead of exceptions across the interface
CollectionsArrayList, HashMap, ConcurrentHashMap, CopyOnWriteArrayList and List.of() in the service, registry and event classes
Event handlingActionListener on the buttons, DocumentListener for the live search, FocusListener for the input fields, MouseListener for the links, WindowAdapter for the windows — plus the own EventBus between the segments
